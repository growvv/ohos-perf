# HapRay parity fixtures

`packages/core/test/fixtures/hapray/` holds the reference payloads the P1
analyzers are compared against. They are generated from HapRay, **not** from
this repository, and the test suite only parses them (see
`packages/core/test/parity-fixtures.test.ts`); no test runs HapRay or Python.

- HapRay revision: `9386e4e`
  (`E:\CodeE\vibe51\performance_rq\performance_rq\hapray_perf_testing`)
- Python (HapRay venv):
  `E:\CodeE\vibe51\performance_rq\performance_rq\hapray_perf_testing\.venv-win\Scripts\python.exe`
- Traces: `spike/out/emu_big.db` (emulator) and `spike/out/real_device.db`
  (real device), the trace_streamer databases from the spike.
- App pids: `16702` on the emulator (`pbench.baseline`) and `6115` on the real
  device (`erviceAbility:1`).

The output tag is the trace file's stem, so `emu_big.db` produces
`*.emu_big.json` and `real_device.db` produces `*.real_device.json`.

Each command writes four fixtures (one per analyzer, tagged with that trace's
stem); the two commands together produce the eight recorded-trace fixtures:

| File | HapRay source |
| --- | --- |
| `fault-tree.<tag>.json` | `FaultTreeAnalyzer` |
| `binder.<tag>.json` | `IpcBinderAnalyzer` (`{}` when the trace has no binder events) |
| `threads.<tag>.json` | `ThreadAnalyzer` |
| `thread-wakeup.<tag>.json` | `analyze_all_threads_wakeup_chain` |

`binder.real_device.json` is `{}` because that trace has no binder events, so
binder parity on the real device is a one-sided assertion: the TypeScript side
must also be empty.

## Synthetic golden

`threads.synthetic.json` is not a recorded-trace fixture. The recorded thread
goldens contain no redundant patterns and no perf samples (their
`redundant_threads`, `score_breakdown` and `summary` are all-zero/empty), so a
regression in the redundancy-scoring port would pass the whole suite. This
fixture is generated by HapRay's own `ThreadAnalyzer` wrapper from a synthetic
wakeup payload, then compared field by field by `parity-hapray.test.ts` (no
`skipIf` — it needs no trace). It is HapRay-formatted, not hand-written.

Input: 20 `idle_worker` threads (ids `100..119`, `total_instructions: 0`,
`thread_info: {thread_name: 'idle_worker', start_ts: 0, end_ts: 10_000_000}`)
and 3 `render_helper` threads (ids `200..202`, `total_instructions: 500`).
Each carries one wakeup thread with `itid`/`tid` equal to the result id,
`pid: 900`, `process_name: 'com.demo'`, `instruction_count: 0`,
`is_system_thread: false`, `wakeup_depth: 0`, ten
`{ts: i*1_000_000, dur: 900_000, state: 'S'}` states and `callchains: []`.

Regenerate it (run with `-I` so site-packages cannot shadow stdlib):

```
"E:\CodeE\vibe51\performance_rq\performance_rq\hapray_perf_testing\.venv-win\Scripts\python.exe" -I - <<'PY'
import sys, json, tempfile
from pathlib import Path
ROOT = r"E:\CodeE\vibe51\performance_rq\performance_rq\hapray_perf_testing"
sys.path.insert(0, ROOT)
import hapray.analyze.thread_analyzer as ta
from hapray.analyze.thread_analyzer import ThreadAnalyzer

OUT = r"E:\CodeE\vibe51\emulator_compelate\packages\core\test\fixtures\hapray\threads.synthetic.json"
STATES = [{"ts": i * 1_000_000, "dur": 900_000, "state": "S"} for i in range(10)]

def result(tid, name, instructions):
    return {
        "thread_id": tid,
        "thread_info": {"thread_name": name, "start_ts": 0, "end_ts": 10_000_000},
        "total_instructions": instructions,
        "wakeup_threads": [{
            "itid": tid, "tid": tid, "thread_name": "idle_worker",
            "pid": 900, "process_name": "com.demo", "instruction_count": 0,
            "is_system_thread": False, "wakeup_depth": 0,
            "thread_states": STATES, "callchains": [],
        }],
    }

PAYLOAD = (
    [result(i, "idle_worker", 0) for i in range(100, 120)]
    + [result(i, "render_helper", 500) for i in range(200, 203)]
)
ta.analyze_all_threads_wakeup_chain = lambda *a, **k: PAYLOAD

# Windows-style absolute scene path: os.path.join mis-splits /tmp/... on this venv.
with tempfile.TemporaryDirectory(
    prefix="hapray-synthetic-", dir=r"C:\Users\32147\AppData\Local\Temp"
) as tmp:
    scene = Path(tmp)
    step = scene / "hiperf" / "step1"
    step.mkdir(parents=True)
    (step / "pids.json").write_text(
        json.dumps({"pids": [900], "process_names": ["com.demo"]}, ensure_ascii=False),
        encoding="utf-8",
    )
    threads = ThreadAnalyzer(str(scene))
    threads.analyze("step1", str(scene / "trace.db"), str(scene / "trace.db"))
    payload = threads.results.get("step1")

Path(OUT).write_bytes(
    (json.dumps(payload, ensure_ascii=False, indent=1) + "\n").encode("utf-8")
)
PY
```

The monkeypatch replaces `analyze_all_threads_wakeup_chain` (the only part that
would read a trace) with the payload above; `ThreadAnalyzer._analyze_impl` then
formats the `step1` output itself. `scene/hiperf/step1/pids.json` must exist or
HapRay reports `no app pids`. The result is written with
`json.dumps(..., ensure_ascii=False, indent=1)` plus a trailing newline, matching
the other goldens byte for byte.

## Notes

- The `FaultTreeAnalyzer` / `IpcBinderAnalyzer` / `ThreadAnalyzer` files are the
  `step1` payload only; the outer `{"step1": ...}` report wrapper is stripped.
- `ThreadWakeup` fixtures keep the same top-level shape as HapRay's result but
  replace each thread's large `thread_states` and `callchains` arrays with
  `thread_states_count` / `callchains_count`. The TypeScript comparison pins
  those counts.
- The script copies the trace into a temporary scene before running HapRay
  because HapRay's wakeup code creates indexes on the database it opens; the
  input trace is left untouched.
